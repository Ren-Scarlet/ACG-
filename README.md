# ACG 卡牌构筑器

一个基于 GitHub Pages、JSON 和浏览器本地存储的 ACG 卡牌收藏与构筑工具，并提供 Tabletop Simulator（TTS）卡组导入模块。

**网页地址：** https://ren-scarlet.github.io/ACG-/

**TTS 导入器说明：** [docs/tts-importer.md](docs/tts-importer.md)

## 玩家使用

1. 打开网页，在「查询我的收藏」或「开始构筑」区域输入自己的玩家编号（例如 `P001`）。
2. 查询收藏后，可以在构筑器中按自己的收藏数量添加卡牌。
3. 在「本地保存的卡组」区域填写名称并保存；也可以重新读取、覆盖保存。
4. 点击分享功能生成卡组链接。收到链接的玩家可以查看卡组预览，也可以把链接交给 TTS 导入器。

网页会在当前浏览器记住上次使用的玩家编号。这个功能只是方便下次填写，**不是身份验证**。

## 本地保存与多人使用

- 卡组保存在玩家自己的浏览器 `localStorage` 中，并按玩家编号分组。
- 不同玩家使用各自的电脑或独立浏览器配置文件时，本地保存互不影响。
- 同一浏览器配置文件可以切换不同玩家编号；卡组数据仍按编号分组，但“上次使用的玩家编号”只有一个，会被最近使用的玩家覆盖。
- 本地卡组不会自动同步到其他设备。更换浏览器、设备或清除网站数据可能导致本地卡组丢失。
- 分享链接包含卡牌 ID 和数量，不包含玩家的本地保存数据；拿到链接的人可以查看该卡组。

## 卡组规则

构筑限制由 `data/deck_rules.json` 控制。当前文件定义礼装卡组数量、特殊攻击卡总数上限、同名卡数量上限，以及对战道具类型。调整规则时应修改该 JSON 文件，不要直接改动构筑逻辑。

对战道具使用独立构筑区。当前版本不会因为构筑或分享而自动扣除玩家收藏中的对战道具。

## 管理员维护

管理员页面支持维护玩家收藏、卡牌资料、卡包资料和卡图。数据文件存放在仓库的 `data/` 目录，卡图存放在 `images/`。

管理员通过 GitHub 授权写入仓库。访问令牌不应公开、分享或提交到仓库；不要把令牌粘贴到聊天、公开页面或代码中。管理员身份与玩家身份验证仍需在后续阶段完善。

## 项目结构

```text
index.html                 网页主程序
data/
  cards.json               卡牌资料
  packs.json               卡包资料
  players.json             玩家编号与名称
  collections.json         玩家收藏数量
  deck_rules.json          构筑规则
images/                    卡牌图片
tts/
  ACG_Importer.lua         TTS 导入器 Lua 模块
docs/
  tts-importer.md          TTS 导入器整合与使用说明
```

## 当前架构与注意事项

- 网页是静态站点，使用 GitHub Pages 发布；公开 JSON 由浏览器读取。
- 玩家本地卡组只存于本机浏览器，不会写入 GitHub 仓库。
- 分享链接使用卡牌稳定 ID。打开旧链接时，网页和 TTS 导入器会按当前公开卡牌资料读取卡名、卡图和效果。
- 当前玩家编号尚不能证明使用者身份。知道其他玩家编号的人可能读取其公开收藏数据；玩家身份验证与权限隔离列为后续工作。
- 请勿将私人信息、密码或访问令牌写入公开 JSON、分享链接或仓库文件。
