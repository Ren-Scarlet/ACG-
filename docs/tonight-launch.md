# 今晚上线步骤

## 1. 先执行数据库迁移

打开 Supabase 项目 → SQL Editor → New query，将本文件同目录的 `tonight-launch.sql` 全部内容粘贴并执行。

执行成功后，最后会返回一张安全状态表，列出关键表是否启用了 RLS 以及策略数量。请保留这份结果，发给开发协助检查；不能只看 SQL 显示 Success 就认为整个数据库已完成安全审计。

这份迁移会：
- 给 `profiles` 增加唯一的玩家编号字段。
- 建立 P001～P012 玩家编号登记表。
- 保存当前 `data/collections.json` 中的旧收藏快照。
- 管理员把玩家编号绑定到注册账号时，自动将对应旧收藏导入 Supabase。
- 提供管理员库存增减功能，并记录调整原因。
- 建立对战道具提交记录与原子扣除函数，防止重复请求重复扣除。
- 保留抽卡卡池关闭状态，不会抽卡或扣除代币。

迁移不会删除旧的 `collections.json`，也不会清空 Supabase 中已有库存。导入旧收藏时，数量会加到该账号现有库存上；每个玩家编号只会自动导入一次。

## 2. 管理员先登录并绑定玩家

1. 先用现有管理员账号登录网站。
2. 打开「玩家中心」。
3. 在管理员面板的「玩家管理」区域，选择玩家编号（例如 P001）和对应的注册账号。
4. 点击「绑定玩家编号并导入旧收藏」。
5. 确认绑定列表显示正确。

玩家编号一旦绑定，普通管理员界面不允许直接改绑，避免误把收藏转给其他账号。

## 3. 玩家注册

让玩家在「玩家账号」页面使用自己的邮箱注册。注册成功后，管理员在玩家中心把对应 P 编号分配给该账号。

玩家完成绑定后，就可以登录并从「卡组构筑」读取自己的 Supabase 收藏。构筑器不再接受手填玩家编号作为身份凭证。

## 4. 对战道具

玩家点击「生成分享链接」时，系统会先检查构筑规则；若卡组含对战道具，就调用数据库事务扣除相应库存。扣除成功后才生成分享链接。重复网络请求使用同一请求编号，不会重复扣除；普通卡牌不会被扣除。

目前公开卡牌目录尚未包含类型为「对战道具」的卡牌，因此这项功能需要在管理员新增第一张对战道具并保存卡牌资料后，才能进行实际验收。保存卡牌资料时，网站会同步对战道具目录。

## 5. TTS 导入器

导入按钮已从左下角移到左上角，避免遮挡聊天框。需要将新版 `tts/ACG_Importer.lua` 重新复制进 TTS Global 脚本并保存存档。不同玩家独立粘贴链接、独立导入的流程保持不变。

## 6. 上线前最后检查

- 管理员账号能登录，玩家编号绑定成功。
- 玩家账号注册后能登录，未绑定前不能读取收藏或构筑。
- 绑定 P001 / P002 后，旧收藏数量与旧数据一致。
- 管理员库存增减能正常工作，不能扣成负数。
- 对战道具目录同步后，构筑确认能扣除道具且不会重复扣除。
- TTS 四名玩家各自导入不同链接，卡牌进入正确手牌区。
- 抽卡卡池继续保持关闭，直到管理员另行决定开放。
